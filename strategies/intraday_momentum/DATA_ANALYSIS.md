# 数据源可行性分析报告

## 1. 策略数据需求汇总

根据策略文档，本策略在交易时段（特别是 09:24:59 和 09:35:01）需要以下核心数据支持：

1.  **实时快照数据 (Snapshot)**：
    - 现价 (Current Price)
    - 开盘价 (Open Price)
    - 最低价 (Low Price)
    - 昨日收盘价 (Pre Close)
    - **量比 (Volume Ratio)** - _核心过滤条件_
    - 集合竞价价格 (Auction Price)
2.  **分时数据 (Intraday Data)**：
    - **分时均线 (VWAP)**：需要当日累计的成交金额 / 累计成交量，或者直接获取已计算好的均价。
    - 持续且准确的时间戳校验 (用于判断 "跌破均线 5 分钟")。

---

## 2. AkShare 可行性分析

**结论：完全可行，推荐使用。**

AkShare 主要对接东方财富等财经网站接口，能够提供高质量的实时行情数据。

| 需求指标                              | AkShare 接口 / 方法                                       | 可行性 | 说明                                                                                                                                 |
| :------------------------------------ | :-------------------------------------------------------- | :----- | :----------------------------------------------------------------------------------------------------------------------------------- |
| **实时行情**<br>(现价/开盘/最低/昨收) | `ak.stock_zh_a_spot_em()`                                 | ✅ 高  | 东财接口，延迟极低，包含所有基础字段。                                                                                               |
| **量比**                              | `ak.stock_zh_a_spot_em()`<br>字段: `量比`                 | ✅ 高  | 接口直接返回"量比"字段，无需自行计算，非常适合本策略。                                                                               |
| **分时均线** (VWAP)                   | 1. `ak.stock_zh_a_minute()` (分时数据)<br>2. 实盘自行计算 | ✅ 中  | 1. 可以获取当日 1 分钟级数据，通过 `cumsum(金额)/cumsum(量)` 计算。<br>2. 很多实时快照接口直接包含“均价”字段（需验证具体字段返回）。 |
| **集合竞价**                          | 09:25 调用实时行情接口                                    | ✅ 高  | 在 09:25 获取的 snapshot 即为集合竞价结果。                                                                                          |

**优势**：

- **数据全**：直接提供策略核心强依赖的“量比”数据。
- **实时性强**：基于爬虫/API 对接实时网页接口，适合盘中监控。
- **免费开源**：无需付费即可使用。

**劣势**：

- **稳定性**：依赖第三方网页结构，若源站改版可能失效（需定期更新库）。
- **请求限制**：高频请求可能面临 IP 限制（建议控制请求频率或使用代理）。

## 3. Baostock 可行性分析

**结论：不可行（不适合日内高频/实时策略）。**

Baostock 定位为由官方提供维护的历史数据下载工具，在这个策略的实时性要求面前存在明显短板。

| 需求指标     | Baostock 接口    | 可行性 | 说明                                                                                                           |
| :----------- | :--------------- | :----- | :------------------------------------------------------------------------------------------------------------- |
| **实时行情** | ❌ 无官方实时流  | ❌ 低  | Baostock 主要提供 T+1 的历史数据，虽然有 `query_history_k_data_plus`，但其实时性无法满足秒级触发（09:35:01）。 |
| **量比**     | ❌ 无直接字段    | ❌ 低  | 历史数据通常不记录“量比”这一瞬时盘口指标，需自行用过去 5 日均量计算，且缺乏实时分钟级成交量，无法准确计算。    |
| **分时均线** | 需特定权限或延迟 | ❌ 低  | 免费版通常难获取当日实时的逐笔或分钟 tick 数据来计算均线。                                                     |

**核心痛点**：

- **缺乏实时性**：无法支持 09:35:01 这种精确到秒级的触发判断。
- **缺失关键指标**：默认不提供实时的“量比”数据。

---

## 4. 综合建议与实施方案

### 建议方案

**使用 AkShare 作为核心数据源。**

### 实施路径

1.  **数据获取 - 盘中轮询 (Loop)**

    - 使用 `ak.stock_zh_a_spot_em()` 每隔固定时间（如 3-5 秒）拉取全市场或自选股池的快照。
    - 该接口一次性返回 DataFrame，包含 `代码`, `名称`, `最新价`, `最高`, `最低`, `今开`, `昨收`, `量比` 等。

2.  **指标计算 - 分时均线**

    - **方案 A (简易)**：若快照接口中有 `均价` 字段，直接使用。
    - **方案 B (精确)**：针对符合初步条件（如量比>2.5）的目标股，单独调用 `ak.stock_zh_a_hist_min_em(symbol=..., period='1', adjust='')` 获取当日分时数据，计算 `sum(成交额)/sum(成交量)` 得到当前分时均价。

3.  **卖出监控 - 集合竞价**
    - 设置定时任务（Crontab 或 Python Schedule），在 **09:24:59** 触发一次全量检测，计算 `(current_price / pre_close) - 1`。
